# M36 v1.0.0 migration guide

**Status:** staged release documentation, not release certification. The M36
plan and [CONFORMANCE.md](../../../CONFORMANCE.md) record the authoritative
scope, evidence, and approved exceptions. This worktree has not asserted a
release commit, tag, package publication, registry result, or full
exact-candidate live pass.

## Runtime and version

The v1 support contract is Node.js 22 or 24, with a package engine requirement
of `>=22`. Node 18 and 20 are outside the v1 contract. Package, lockfile, CLI,
and CI alignment is complete in the worktree; exact-candidate and publication
gates remain open, so this is not proof that a registry artifact exists.

`a2l --version` and `a2l -V` each write exactly one stdout line and exit 0:

```text
agent2linear 1.0.0
```

## Required command replacements

| Previous pattern                                                       | v1 replacement                                                                | Notes                                                                            |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `--api-key <key>` or `--api-key -`                                     | `--api-key-file <path-or-stdin>`                                              | Literal argv keys are removed. `-` reads the key from stdin.                     |
| `config ... apiKey ...` supplied through argv                          | key file, workspace env variable, profile env-file, or local secrets registry | Raw `apiKey` argv input is rejected. Committable config must not hold a raw key. |
| `issue comment <identifier> --body ...`                                | `issue comment add <identifier> --body ...`                                   | The removed route exits 2 with a migration suggestion.                           |
| Changed `issue` or `project` list result selection with `-f, --format` | `-o, --output` or `--json`                                                    | JSON list results are resource envelopes, not bare arrays.                       |
| `labels`, `lbl`, or `labels list` as a CRUD surface                    | `issue-labels list` or `project-labels list`                                  | The old spelling is a compatibility help shim only.                              |
| Treating `--all` as retired-label scope                                | Add `--include-retired` when needed                                           | `--all` only exhausts cursor pages.                                              |
| `alias clear ... --force` as consent                                   | `alias clear ... -y` / `--yes`                                                | Inspect first with `--dry-run`; no prompt is allowed with `--no-input`.          |

Use a file or a named environment variable for keys; do not pass a key in shell
history or a command line. A command reading `--api-key-file -` owns stdin, so
it cannot also read a comment body or another stdin input.

## Output, streams, and exits

Changed result commands use an explicit selector. `--json` is equivalent to
`--output json`; combining `--json --output table` is a usage error. Changed
label lists accept `table|json|tsv`, while changed label lifecycle mutations
accept `table|json`.

- Successful result data goes to stdout. Diagnostics and remediation go to
  stderr; keep the streams separate when scripting.
- JSON success and failure use stable command-specific result/error envelopes
  for the named M36 inventory. Mutations commonly expose `ok`; read commands
  expose their resource and pagination fields. Parse the documented envelope
  rather than scraping prose.
- Exit 0 is success, exit 1 is an operational/API failure, exit 2 is usage or
  validation, exit 3 is not found, exit 4 is authentication/authorization,
  and exit 5 is a conflict or rejected cursor. Signal exits remain 130 for
  SIGINT and 143 for SIGTERM.
- Not-found behavior is command-aware: human-readable `issue view` and
  `project view` report a typed not-found failure without a stack trace; JSON
  mode retains the machine-readable error contract.

The M36 inventory deliberately does not erase every legacy surface. Fifteen
legacy result commands retain `-f, --format`, and twelve JSON-only legacy
selectors remain. Do not mechanically replace those selectors unless the
specific command documents the new output contract.

## Cursor pagination and local history

Lists are cursor based. `--limit` is bounded from 1 through 250; copy the raw,
opaque `pageInfo.endCursor` value into `--after` for the next page. `--all`
continues through remaining pages. There is no numeric `--page`, direct page-N
jump, backward `--before`, or `--cursor` synonym.

Human truncated output prints a copyable next-page command and a
cursor-history entry ID. JSON results expose `pageInfo` and `cursorHistory`.
Use `--no-cursor-history` when retaining the query/target context locally is
not appropriate. Manage retained entries with:

```bash
a2l cursor-history list
a2l cursor-history view <entry-id>
a2l cursor-history clear --dry-run
a2l cursor-history clear --yes
```

## Write safety and dry runs

`--dry-run` is the safety default for planned mutations: it must make neither
remote Linear writes nor local state/config writes, and it does not prompt.
Use it before `alias clear`, comment/issue/project mutation, label lifecycle
mutation, alias synchronization, configuration override, or cursor-history
clear. `--no-input` prevents a prompt; `-y, --yes` is explicit consent for a
real write.

The v1 dry-run guarantee is bounded to the named M36 mutation inventory, not a
claim that every command in the historical CLI is dry-run capable. Consult
command help before automating an older command.

## Accepted compatibility boundaries

M36 is an audited release with approved boundaries, not a claim of universal
redesign. The current accepted exceptions include plural canonical command
groups, legacy output selectors outside the named inventory, credential naming
and config-layering parity, JSON config support, existing environment-variable
names, Commander help shape, legacy direct exits, locale comparison behavior,
and the existing workspace/profile authentication model.

Approved waivers include nested body input handling, bounded rather than
universal dry-run coverage, malformed discovered config handling, partial batch
failure behavior, progress/order details, shell completions, app-wide timeout
and retry policy, empty-state presentation, doctor machine errors,
raw-cursor-only pagination, and centralized rate-limit policy. Their owners
and rationale are in [CONFORMANCE.md](../../../CONFORMANCE.md); they are not
silent promises of v1 behavior.

## Verify before adopting a release

Use this guide only after the release operator has completed the plan’s version
alignment, static/CI, candidate live, package inspection, registry, tag, and
rollback gates. Until then, do not pin an npm version, assume an artifact is
published, or attach a commit SHA to these notes.
